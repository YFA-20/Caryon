Scope : 49 composants React, 15 pages, design system Tailwind.
Méthode : scan statique systématique du code source + tests automatisés (`tests/unit/a11y.test.ts`, 27 tests).

## Corrections appliquées (cette PR)

1. **Skip link** : lien « Aller au contenu principal » en début du shell, visible au focus clavier, pointant vers `<main id="main-content" tabIndex={-1}>`.
2. **Kanban clavier** : `KeyboardSensor` + `sortableKeyboardCoordinates` ajoutés. Les cartes ont `role="button"`, `tabIndex={0}`, et un `aria-label` avec instructions (Espace pour saisir, flèches pour déplacer, Entrée pour déposer).
3. **Focus trap** : nouveau hook `useFocusTrap` appliqué aux 3 modales (consentement IA, onboarding, palette de commandes). Tab/Shift+Tab bouclent dans la modale, le focus revient à l'élément d'origine à la fermeture.
4. **Hiérarchie des titres** : `h3` → `h2` dans la liste des candidatures (saut h1→h3 corrigé).
5. **Tableau** : `scope="col"` sur tous les `<th>`, `aria-label` sur les boutons de tri.

## Déjà en place avant l'audit

- Contraste : toutes les combinaisons texte/fond >= 6.0:1 (AAA pour la plupart).
- `lang="fr"`, titre de page descriptif.
- `:focus-visible` global avec ring 2px lavender + offset.
- `prefers-reduced-motion: reduce` désactive animations et transitions.
- 247 icônes décoratives avec `aria-hidden`.
- 35 boutons icône avec `aria-label`.
- 18 zones `role="alert"` / `role="status"` / `aria-live="polite"`.
- 3 modales avec `role="dialog"`, `aria-modal="true"`, `aria-label`/`aria-labelledby`.
- Landmarks sémantiques : `<main>`, `<nav>` (sidebar, drawer, header).
- Tous les formulaires ont des `<label htmlFor>` ou `aria-label`.
- Aucun `tabIndex` positif, aucun élément cliquable non focusable.
- Raccourcis clavier globaux désactivés dans les champs de saisie.

## Limites de l'audit

- Audit statique + tests automatisés. Un test manuel avec lecteur d'écran (NVDA/VoiceOver) reste recommandé avant la v1.0.0.
- Les tests E2E Playwright (CI) couvrent les parcours principaux mais pas tous les états d'erreur.
- Le contraste est calculé sur les tokens du design system ; les états hover/focus utilisent les mêmes tokens.
